# 결제경로 파일

결제경로 파일은 카드사 심사를 위해 **결제가 이루어지는 과정을 화면 캡처로 보여주는 PPT**입니다. 흐름은 메인 페이지 → 상품 선택 → 결제 → 결제창 확인입니다.

- **결제경로 파일이 없으면 심사를 진행할 수 없습니다.** 심사 계정을 주더라도 따로 제출합니다.
- **PDF가 아닌 PPT로** 계약 담당자에게 보냅니다. 카드사마다 양식을 고쳐 쓰기 때문입니다.
- 토스 계약과정 FAQ에 업종별 예시 파일이 있습니다. 이 템플릿은 **정기결제(빌링)용** 가이드를 따릅니다.

## 구성 순서

공식 가이드의 6단계에 이 템플릿의 화면을 연결한 표입니다.

| 단계 | 담을 내용 | 템플릿 화면 |
| --- | --- | --- |
| ① 가맹점 정보 | 표지에 상호명, 사업자등록번호, **운영** URL, 운영 계정 ID/PW | 직접 작성 |
| ② 하단 정보 | 상호명, 대표자명, 사업자등록번호, 통신판매업 신고번호, 사업장 주소, **유선전화번호** | 모든 화면 하단의 푸터 |
| ③ 환불 규정 | 환불 규정 전문. 무형 상품은 일할 계산 기준이 보이게 | `/policies/refund` |
| ④ 로그인 | 운영 계정으로 로그인하는 과정. 비회원 구매가 되면 비회원 구매 경로 | `/login` |
| ⑤ 상품 선택과 구매 | 상품 선택부터 결제하기 버튼까지 이어지는 과정 | `/` 요금제 → `/subscribe` → `/payment-method` 동의 |
| ⑥ 카드 결제 | **정기결제용 카드 입력창까지** 캡처 | 토스 카드 등록창, 자체 입력창 |

### 단계별 캡처 목록

| 장 | 단계 | 화면 | 표시할 곳 |
| --- | --- | --- | --- |
| 1 | ① | 표지 | 상호명, 사업자등록번호, 운영 URL, 운영 계정 ID/PW |
| 2 | ② | 랜딩 하단 푸터 | 사업자정보 영역 |
| 3 | ③ | 취소·환불 규정 | 환불 기준 표와 즉시 해지 계산 |
| 4 | ④ | 로그인 | 아이디·비밀번호 입력과 로그인 버튼 |
| 5 | ⑤ | 랜딩 요금제 | 상품명, 이미지, 상세 설명, 부가세 포함 금액, 서비스 제공기간, 구독 시작 버튼 |
| 6 | ⑤ | 구독 결제 | 주문 내용, 결제 금액, 최종 동의, 결제 버튼 |
| 7 | ⑤ | 자동결제 동의 | 동의 항목과 카드 등록 방식 버튼 |
| 8 | ⑥ | 토스 카드 등록창 | 카드 정보 입력과 본인 정보 입력 화면 |
| 9 | ⑥ | 자체 입력창 | 카드번호, 유효기간, 생년월일, 비밀번호 앞 2자리 |
| 10 | ⑥ | 결제 완료 | 구독 시작 안내와 다음 결제일 |

자체 입력창을 쓰지 않기로 했다면 9장을 뺍니다. 카드 등록 뒤 결제가 진행되는 구조이므로 10장까지 넣어 흐름이 끊기지 않게 합니다.

## 캡처 규칙

공식 가이드의 유의사항입니다. 지키지 않으면 카드사 심사가 정상적으로 진행되지 않습니다.

1. **반드시 PPT 형식**으로 만듭니다.
2. **북마크바 없이 도메인이 보이게** 캡처합니다. 주소창의 도메인이 화면 위쪽에 보여야 합니다.
3. **PC의 시계가 함께 보이게** 캡처합니다. 카드사가 시간의 흐름을 보고 조작 여부를 판단합니다. 브라우저 창만 잘라 내지 말고 작업 표시줄의 시계까지 포함하세요.
4. 상품·서비스의 명칭, 이미지, 상세 설명, 금액, 결제 페이지, 결제창의 흐름이 모두 확인되어야 합니다.
5. 상품을 구매할 때 쓰는 **계정과 로그인 과정**을 캡처합니다. 이 계정은 회신 메일에 적은 운영 계정과 같아야 합니다.
6. **테스트 결제창으로 연동된 상태에서도 심사가 가능**합니다. 계약 전에는 테스트 키로 연 결제창을 캡처합니다.
7. 안심키인을 써서 결제창이 없는 경우에만 결제창 캡처를 생략할 수 있습니다.

이 템플릿에서 추가로 지킬 것입니다.

- **주소창에는 운영 도메인만 보여야 합니다.** `dev.`, `test.`, `staging.` 같은 개발·테스트 주소나 `localhost`에서 캡처하면 안 됩니다([운영 URL과 운영 계정](07-contract-review-reply.md#운영-url과-운영-계정만-쓴다)).
- 운영 도메인에 운영 빌드(`npm run build`)로 배포한 화면을 캡처합니다. 미리보기 안내 띠, 노란색 자리표시, `/toss-example` 화면이 보이면 안 됩니다.
- 카드 번호와 생년월일은 테스트 값이라도 가립니다.
- 각 장에 누를 버튼을 상자로 표시하고, 다음 화면으로 넘어가는 동작을 한 줄로 적습니다.

## 점검

- [ ] 6단계가 모두 들어 있다
- [ ] 모든 캡처에 도메인과 PC 시계가 보인다
- [ ] 모든 캡처의 도메인이 운영 도메인이고, 로그인한 계정이 회신한 운영 계정이다
- [ ] 하단 정보 캡처에 유선전화번호까지 6개 항목이 모두 있다
- [ ] 상품명, 이미지, 설명, 금액, 서비스 제공기간이 보인다
- [ ] 카드 입력창까지 캡처했다
- [ ] 화면의 가격과 사업자정보가 실제 사이트와 같다
- [ ] PPT(`.pptx`)로 저장했다
