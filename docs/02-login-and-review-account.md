# 로그인과 심사 계정

회원만 결제할 수 있는 서비스는 심사 담당자가 결제 경로까지 들어갈 방법이 있어야 합니다. 계약 심사 메일은 다음 두 가지를 모두 요구합니다.

| 제출물 | 내용 | 제출 방법 |
| --- | --- | --- |
| 테스트 계정 | 운영 서버에 만든 운영 계정의 아이디와 비밀번호. **test 같은 테스트용 아이디, 소셜 로그인 계정 불가** | [계약 심사 메일 회신](07-contract-review-reply.md#테스트-계정-idpw)에 기재 |
| 결제경로 파일 | 예시 파일과 같은 구성의 PPT | [결제경로 파일](08-payment-path-file.md)을 회신에 첨부 |

토스 블로그는 둘 중 하나를 고르라고 안내하지만, 계약 심사 메일은 둘 다 요구합니다. 메일을 기준으로 준비하세요.

## 실제 로그인이어야 하는 이유

화면에서 특정 아이디·비밀번호만 통과시키는 방식은 쓰지 마세요.

- 브라우저에는 로그인된 것처럼 보여도 서버 토큰이 없어 모든 API가 401을 돌려줍니다. 로그인 후 화면에 데이터가 나오지 않아 심사 담당자가 결제 경로를 확인할 수 없습니다.
- 자격 증명이 배포 파일에 그대로 들어가 누구나 볼 수 있습니다.

운영 DB에 실제 계정을 만드는 것이 가장 빠르고 안전합니다.

## 화면 요구 사항

참고 화면: [LoginPage.tsx](../web/src/pages/LoginPage.tsx), 복귀 주소 검증: [safe-next-path.ts](../web/src/auth/safe-next-path.ts)

| 항목 | 내용 |
| --- | --- |
| 입력 | 아이디, 비밀번호. 비밀번호 보기 버튼 |
| 자동 완성 | `autocomplete="username"`, `autocomplete="current-password"` |
| 버튼 | 두 칸을 채우면 활성화. 요청 중 비활성화하고 `로그인 중...` 표시 |
| 실패 | 비밀번호를 지우고 안내 문구 표시 |
| 복귀 | 로그인 전에 보던 화면으로 이동 |
| 푸터 | 로그인 화면에도 사업자 정보 표시 |

## 서버 요구 사항

| 항목 | 내용 |
| --- | --- |
| 비밀번호 저장 | bcrypt나 argon2 같은 단방향 해시 |
| 실패 문구 | 계정 존재 여부가 드러나지 않게 같은 문구 사용: `아이디 또는 비밀번호가 일치하지 않습니다.` |
| 세션 | `HttpOnly`, `Secure`, `SameSite` 쿠키 |
| 전송 | HTTPS만 허용 |
| 시도 제한 | 반복 실패를 제한. 심사 기간에 심사 계정이 잠기지 않는지 확인 |
| 복귀 주소 | `next` 값은 자사 경로만 허용. 외부 주소로 보내면 피싱에 악용됩니다 |

```text
POST /api/auth/login   { "loginId": "...", "password": "..." }
  200 { "loginId": "...", "name": "...", "email": "..." }
  401 { "code": "AUTH_FAILED", "message": "아이디 또는 비밀번호가 일치하지 않습니다." }

GET  /api/auth/me      로그인 상태면 200 사용자 정보, 아니면 401
POST /api/auth/logout  204
```

## 심사 계정 준비

1. **운영 서버(운영 DB)**에 심사용 계정을 만듭니다. 개발·스테이징 서버의 계정은 안 됩니다. 아이디는 `test`, `test01`, `demo`처럼 테스트용으로 보이는 이름이 아니라 실제 회원 계정과 같은 형식으로 만듭니다([운영 URL과 운영 계정](07-contract-review-reply.md#운영-url과-운영-계정만-쓴다)). 관리자 권한이 아니라 일반 결제 회원 권한이면 충분합니다.
2. 실제 데이터가 보이도록 필요한 값을 넣어 둡니다.
3. 결제 경로를 끝까지 따라가 봅니다. 구독 시작, 동의, 토스 결제창까지 막히면 안 됩니다.
4. 심사 계정에 휴대폰 인증이나 2단계 인증이 걸려 있으면 심사 담당자가 통과할 수 없습니다. 별도 방식을 준비합니다.
5. 카카오, 네이버, 구글 같은 소셜 로그인만 지원하는 서비스라면 심사용 아이디·비밀번호 로그인을 따로 엽니다. 소셜 로그인 계정은 받지 않습니다.
6. 강한 비밀번호를 만들어 계약 심사 메일 회신에 적습니다. 공개 게시판이나 사이트 화면에 적지 마세요.
7. 심사가 끝나면 계정을 비활성화합니다.

결제까지의 화면을 담은 PPT는 [결제경로 파일](08-payment-path-file.md)을 보세요.

## 점검

- [ ] 시크릿 창에서 운영 도메인을 열고, 아이디·비밀번호 심사 계정으로 로그인된다
- [ ] 심사 계정이 운영 서버에 있고, 아이디가 test나 demo 같은 테스트용 이름이 아니다
- [ ] 로그인 후 네트워크 탭에 401이 없다
- [ ] 비밀번호 틀림과 없는 아이디의 문구가 같다
- [ ] `/login?next=https://example.com` 으로 로그인해도 외부로 나가지 않는다
- [ ] 자격 증명이 소스 코드나 배포 파일에 없다
