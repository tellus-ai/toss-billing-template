# 계약 심사 메일 회신

토스페이먼츠에 가입을 신청하면 계약 담당자가 두 가지를 요청하는 메일을 보냅니다.

1. 계약 심사를 위한 필수 질문에 대한 답변
2. 카드사 심사를 위한 홈페이지 준비사항 확인

이 문서는 그 메일에 이 템플릿 기준으로 회신하는 방법입니다. 메일 문구는 상점마다 조금씩 다를 수 있으니 받은 메일을 기준으로 맞추세요.

## 반드시 지킬 것

### 운영 URL과 운영 계정만 쓴다

회신 메일, 결제경로 PPT, 심사 담당자에게 주는 모든 주소와 계정은 **실제로 운영 중인 서비스의 것**이어야 합니다.

| 구분 | 쓰면 안 되는 것 | 써야 하는 것 |
| --- | --- | --- |
| URL | `dev.`, `test.`, `stg.`, `staging.` 같은 개발·테스트 주소, `localhost`, IP 주소, 배포 미리보기 주소 | 고객이 실제로 접속하는 운영 도메인 |
| 계정 | `test`, `test01`, `demo`, `dev`처럼 테스트용으로 보이는 아이디, 개발 서버에만 있는 계정 | 운영 서버(운영 DB)에 만든 실제 회원 계정 |

- 토스 양식의 항목 이름은 "테스트계정"이지만, 여기에 적는 것은 운영 서비스에 실제로 로그인되는 계정입니다.
- 결제창은 계약 전이라 테스트 키로 열려도 됩니다. 다만 그 결제창을 여는 사이트는 운영 도메인이어야 합니다.

### 서류는 3개월 이내 발급분만 낸다

계약에 제출하는 서류는 모두 **발급일로부터 3개월 이내**의 문서로 준비합니다. 3개월이 지난 서류는 다시 발급받아야 합니다. 열람용이나 팩스용이 아닌 제출용이어야 합니다. 서류 목록은 [제출 서류](#제출-서류)에 있습니다.

## 제출 서류

신청한 날 받은 **'수정권한 메일'**로 서류를 올립니다. 메일이 오지 않았다면 계약 담당자에게 재발송을 요청합니다.

| 사업자 구분 | 서류 |
| --- | --- |
| 개인사업자 | 사업자등록증 |
| 법인사업자 | 사업자등록증, 법인등기부등본, 주주명부, 법인인감증명서 |
| 대리인이 신청 | 위 서류 + 대리인 위임장 (FAQ의 양식 사용) |

모든 서류는 **발급일로부터 3개월 이내**여야 합니다.

| 서류 | 유효 조건 |
| --- | --- |
| 사업자등록증 | 열람용이 아닌 **제출용**, 3개월 이내 발급분. 사업자등록증명으로 내도 3개월 이내 |
| 법인등기부등본 | 3개월 이내, **제출용**, 뒷장까지 전부. 열람용이나 팩스용이면 재발급. 지점은 같은 법인등록번호의 법인 등기부 |
| 주주명부 | 3개월 이내. 실제소유자의 성명, 생년월일, 성별, 국적, 지분율(%) 기재. 인감증명서와 같은 **법인인감 날인** |
| 법인인감증명서 | 3개월 이내 |
| 대리인 위임장 | FAQ의 양식으로 작성. 3개월 이내 작성분 |

## 기한과 문의

- 계약이 끝나지 않은 상태에서 **1개월 넘게 회신하지 않으면 신청이 취소**됩니다. 다시 진행하려면 재신청해야 합니다.
- 계약 관련 문의는 받은 메일에 회신합니다. 그 외 문의는 1544-7772로 합니다.
- 결제 연동 같은 개발 문의는 계약 부서가 아니라 기술지원팀이 받습니다. 답변까지 1~2영업일 걸릴 수 있습니다. 1544-7772(내선 2~4번), techsupport@tosspayments.com, [디스코드](https://discord.com/invite/VdkfJnknD9)
- 홈페이지 준비와 [결제경로 파일](08-payment-path-file.md)을 먼저 끝내고 한 번에 회신하는 편이 빠릅니다.

## 1. 필수 질문 회신

### 회신 양식

대괄호를 채워 그대로 보낼 수 있습니다.

```text
1. 상품/서비스 정보
① 결제 상품/서비스 확인 가능한 URL: https://[운영 도메인]/
② 환불 정책 확인 가능한 URL: https://[운영 도메인]/policies/refund
③ 결제 상품/서비스 상세 내용: [아래 작성 예시 참고]
④ 단건 결제 기준 상품 금액 최고가: [금액]원
테스트계정 ID/PW: [운영 계정 아이디] / [비밀번호]

2. 최대 서비스 제공기간
① 최대 제공기간: 1개월 (월 단위 정기결제, 결제일부터 다음 결제일 전날까지)

3. 앱 다운로드 링크: 해당 없음 (웹에서만 결제)

4. 결제모듈 직접 연동 여부: Y
```

### ① 결제 상품/서비스 URL

- 로그인 없이 상품 이름, 이미지, 부가세 포함 가격이 보이는 공개 페이지를 적습니다. 템플릿에서는 랜딩(`/`)입니다.
- 운영 도메인이어야 합니다. `dev.`, `test.`, `staging.` 같은 개발·테스트 주소, `localhost`, 미리보기 빌드 주소는 안 됩니다([운영 URL과 운영 계정](#운영-url과-운영-계정만-쓴다)).

### ② 환불 정책 URL

- 로그인 없이 열리는 취소·환불 규정 전문 주소를 적습니다. 템플릿에서는 `/policies/refund` 입니다.
- 회신한 뒤에는 주소를 바꾸지 마세요. 심사 중에 링크가 깨지면 다시 확인을 요청받습니다.

### ③ 상품/서비스 상세 내용

계약은 정기결제와 자동결제 두 유형으로 심사받으므로 둘 다 설명합니다. 작성 예시입니다.

```text
[서비스명]은 [대상 고객]에게 [핵심 기능]을 제공하는 온라인 구독 서비스입니다.
월 [구독료]원(부가세 포함)을 매월 같은 날 정기결제하며, 한 달에 [제공량]을 제공합니다.
제공량을 넘겨 사용한 부분은 1[단위]당 [단가]원(부가세 포함)으로 계산해
다음 결제일에 구독료와 합산해 자동결제합니다. 추가 사용료는 한 달에 최대 [상한]원입니다.
실물 배송은 없으며 결제가 승인되면 즉시 온라인으로 이용할 수 있습니다.
회원은 구독 관리 화면에서 언제든 해지할 수 있고, 결제한 기간의 마지막 날까지 이용합니다.
```

### ④ 단건 결제 최고가

이 구조는 한 번의 결제에 **구독료와 지난 주기 추가 사용료를 합산**합니다. 추가 사용료에 상한이 없으면 회신한 최고가보다 큰 결제가 나갈 수 있습니다.

1. 한 주기의 추가 사용료 상한을 정합니다. 상한에 닿으면 사용을 막을지, 그 이상은 청구하지 않을지 정책으로 정합니다.
2. 최고가를 계산합니다.

   ```text
   단건 결제 최고가 = 월 구독료 × 최대 구매 수량 + 추가 사용료 상한
   예) 33,000원 × 1 + 1,100원 × 100시간 = 143,000원
   ```

3. 서버의 정기 갱신이 이 금액을 넘는 청구를 하지 않게 막습니다([정기 갱신](04-toss-integration.md#6-정기-갱신)).
4. 상한을 이용약관과 랜딩에도 적습니다([대조표](06-policy-documents.md#약관화면서버-대조표)).

500만 원 이상은 카드사 심사가 반려되거나 별도 협의가 필요할 수 있습니다. 상품·서비스에 따라 **정산주기가 달라지거나 보증보험 가입을 요청**받을 수 있으니, 요청받으면 그 조건으로 진행합니다.

### 테스트 계정 ID/PW

- 비회원이 구매할 수 없는 서비스는 필수입니다. 이 템플릿은 로그인 후에만 결제하므로 반드시 적습니다.
- **운영 서버에 만든 운영 계정**을 적습니다. `test`처럼 테스트용으로 보이는 아이디나 개발 서버에만 있는 계정은 안 됩니다.
- **소셜 로그인 계정은 받지 않습니다.** 카카오, 네이버, 구글 로그인만 지원한다면 심사용 아이디·비밀번호 로그인을 따로 열어야 합니다.
- 계정 준비 방법은 [로그인과 심사 계정](02-login-and-review-account.md#심사-계정-준비)을 보세요.

### 2) 최대 서비스 제공기간

결제 한 번으로 서비스를 제공하는 최대 기간입니다. 이 템플릿은 월 단위 결제이므로 **1개월**입니다.

| 기준 | 내용 |
| --- | --- |
| 12개월 초과 | 입점 불가 |
| 6개월 초과 | 가상계좌 결제수단 사용 불가. 이 템플릿은 카드만 쓰므로 영향 없음 |
| 배송 6주 초과 | 입점 불가. 무형 서비스는 해당 없음 |
| 표시 의무 | 구매자가 제공기간을 알 수 있게 상품 페이지에 명확히 기재 |

- 템플릿은 랜딩의 "서비스 제공 방법"과 구독 결제 화면의 "이용 기간"에 기간을 표시합니다. 담당자가 숫자로 된 기간을 요구하면 `결제일부터 1개월(다음 결제일 전날까지)`처럼 고쳐 적으세요.
- 연간 요금제를 추가하면 최대 제공기간은 12개월이 되고 가상계좌를 쓸 수 없습니다. 회신 값도 함께 바꿉니다.

### 3) 앱 다운로드 링크

- 웹에서만 결제하면 `해당 없음`이라고 적습니다.
- 앱에서 결제하면 스토어 링크를 적습니다.
- 아직 스토어에 등록하지 않았다면 **앱을 소개하는 웹 페이지 링크**와 **APK 다운로드 링크**로 먼저 심사받을 수 있습니다. APK는 파일이 아니라 내려받을 수 있는 링크로 보내야 합니다.
- 앱은 사업자정보를 꼭 하단 푸터에 두지 않아도 되지만, 앱 안 어딘가에는 반드시 적어야 합니다.

### 4) 결제모듈 직접 연동 여부

- 이 템플릿은 토스페이먼츠 SDK와 API를 직접 연동하므로 `Y` 입니다.
- 카페24, 식스샵, 포트원(구 아임포트), 아임웹, 가비아, SIR(영카트, 그누보드), 코드엠 같은 호스팅사나 연동 대행을 쓰면 그 이름을 적습니다. 포트원을 쓰면 이 템플릿의 토스 호출 코드는 포트원 SDK 방식으로 바뀝니다.

## 2. 홈페이지 준비사항 회신

메일의 네 항목과 템플릿 위치입니다. 모두 마친 뒤 "준비 완료"로 회신합니다.

| 메일 항목 | 할 일 | 템플릿 위치 | 문서 |
| --- | --- | --- | --- |
| 실제 판매 상품 1개 이상 | 테스트 상품 불가. 실제 이름과 판매가로 게시 | `config.ts`의 `plan`, `LandingPage` | [05](05-subscription-pages.md) |
| 하단 사업자정보 | 상호명, 대표자명, 사업자등록번호, 사업장 주소(층수·동호수까지), 유선번호를 사업자등록증과 완전히 같게 기재 | `config.ts`의 `company`, `SiteFooter` | [03](03-footer.md) |
| 결제창 연동 | 운영 도메인에서 결제창이 실제로 열리는 상태 | `ConsentStep`, `billing-auth.ts` | [04](04-toss-integration.md) |
| 결제경로 파일 | 예시 파일과 같은 구성의 PPT 첨부 | 템플릿 화면 캡처 | [08](08-payment-path-file.md) |

**템플릿 푸터는 현재 유선번호를 표시하지 않습니다.** 메일, 계약과정 FAQ, 결제경로 제작 가이드가 모두 유선번호를 하단 필수 항목으로 요구하므로 회신 전에 [푸터에 추가](03-footer.md#표시-항목)하세요.

통신판매업 신고번호가 아직 없어도 PG 계약과 카드사 심사를 진행할 수 있습니다. 국민카드 심사만 빠지고, 다른 카드사 심사를 먼저 받으면 됩니다.

## 회신 뒤: 진행 현황 확인

카드사 심사 현황은 [상점관리자](https://app.tosspayments.com/)의 **이용정보 → 결제·부가서비스**에서 봅니다.

처음 로그인할 때는 [tosspayments.com](https://www.tosspayments.com/) 오른쪽 위 **로그인**을 누르고, 아이디에 전자계약 신청 때 적은 이메일을, 비밀번호에 메일로 받은 임시 비밀번호를 넣습니다. 비밀번호를 모르면 비밀번호 찾기를 합니다.

카드사 심사 기간에 지켜야 할 것은 [심사 기간 중 유의할 점](01-card-review-checklist.md#카드사-심사-기간-중-유의할-점)을 보세요.

## 회신 전 점검

- [ ] 회신하는 모든 URL이 운영 도메인이다 (dev, test, staging 주소 없음)
- [ ] 두 URL이 시크릿 창에서 로그인 없이 열린다
- [ ] 랜딩의 상품명과 가격이 실제 판매 조건이다 (테스트 상품, 임시 가격 없음)
- [ ] 상세 내용에 정기결제와 추가 사용료 합산 자동결제를 모두 적었다
- [ ] 회신한 단건 최고가를 넘는 청구가 서버에서 막혀 있다
- [ ] 회신한 계정이 운영 서버의 운영 계정이고, 아이디·비밀번호로 운영 도메인에서 로그인된다
- [ ] 상품 페이지에 서비스 제공기간이 보인다
- [ ] 푸터에 유선번호가 있고 주소에 층수·동호수까지 있다
- [ ] 결제경로 PPT를 첨부했다
- [ ] 모든 서류가 제출용이고 발급일로부터 3개월 이내다
- [ ] 메일을 받은 지 1개월이 지나지 않았다
